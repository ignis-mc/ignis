`block_states.nbt` is a sequence of network-little-endian NBT compounds
`{name, states, version}`, one per block state, in the order Dragonfly
registers them. `ignis.world.block_registry` loads it.

`vanilla_items.nbt` is one network-little-endian compound mapping each item
name to `{runtime_id, component_based, version, data?}`: the item table
StartGame carries and the item runtime IDs. `ignis.world.item` loads it.

`creative_items.nbt` is one network-little-endian compound `{groups: [{category,
name, icon}], items: [{name, meta, nbt?, block_properties?, group_index?}]}`:
the creative inventory. `ignis.item.creative.creative` loads it.

The recipe files are network-little-endian NBT: `crafting_data.nbt` a
compound `{shaped, shapeless, shulker_box, multi}`, the smithing files lists
of recipes and `potion_data.nbt` `{potions, container_changes}`;
`item_tags.json` maps item tags to item names. `ignis.item.recipe.vanilla`
loads them.

`data_driven_blocks.nbt` is one little-endian compound `{blocks: [{name,
components}]}`: the vanilla blocks StartGame must list for the client to
build the same block palette as the server (Go `world.DataDrivenBlocks`).
Without them the client's sequential runtime IDs are shifted and chunks
render as the wrong blocks. `ignis.server.server` loads it.

`biome_definitions.bin` is the payload of the `BiomeDefinitionList` packet
Dragonfly's session sends on join, generated until the biome registry is
ported. `ignis.session.session` loads it.

`legacy_states.nbt` maps pre-1.13 `{name, meta}` blocks to flattened states
(network-little-endian `{legacy, updated}` compounds); the schemas upgrade
stored block states to the current version. Both are loaded by
`ignis.world.chunk.conversion.Upgrades` for the world provider.

When Dragonfly is bumped, copy the new files, update this table, and
regenerate the test vectors with `interop/world` and `interop/items` (see
their `main.go`).
